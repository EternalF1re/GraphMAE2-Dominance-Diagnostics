## Fixed experiment protocol

- Dataset `ogbn-arxiv` only. Batch size 128, no data or split change. Nine runs: each of `Aligned-MTL`, `Nash-MTL`, and `FAMO` with pretraining seeds 0, 1, 2. Each run has 12 epochs and 8532 optimizer updates, using the existing frozen per-seed root/LC batch/RNG schedules (private schedule identifiers omitted from this public copy). No performance-triggered early stop.
- Same model/teacher initialization, optimizer/scheduler budget, mask/remask RNG, model-gradient clipping norm 3, representation extraction, split-safe linear probe, and fixed probe seeds 54321, 54322, 54323 as the frozen baseline comparison. No test-set access during training, diagnostic extraction, validation, or benchmark.
- Checkpoint roles and optimizer updates: `update250=250`, `epoch1=711`, `epoch2=1422`, `epoch3=2133`, `epoch5=3555`, `epoch8=5688`, `epoch12=8532`. Do not add or select other formal comparison points. For each role, use the existing three diagnostic schedule positions 0, 355, 710, with the same target-node representation definition and deterministic batch selection. Keep probe seeds and role grid unchanged.
- All three new methods receive raw `[L_rec, L_lat]` in this order, without lambda=10 pre-scaling or cross-method input normalization. This matches historical dynamic-weighting inputs; method-internal operations are reported explicitly.
- Nash-MTL and Aligned-MTL use the ordered trainable `model.encoder.named_parameters()` GNN encoder set for their objective-specific parameter gradients. Names, shapes, dtypes and order are frozen per run. Branch-only gradients retain method-correct behavior; never substitute full-model PCGrad gradients or GradNorm representation gradients for this set. FAMO uses no separate per-task parameter gradient matrix.

## Fixed method settings and attribution

- **Aligned-MTL:** author `amtl` path, `scale_mode='min'`, `scale_decoder_grad=False`; keep its shared-gradient transformation and unscaled branch-only gradients. `torch.linalg.eigh` may replace removed `torch.symeig` without changing the symmetric eigendecomposition. Log transformation matrix, rank, singular spectrum, and direct row-sum coefficients. Direct R-hat is labeled **pre-transformation representation-level** by default. A post-transformation relative coefficient is additionally eligible only when directly exported from the official transformation, finite, positive, and unambiguous; no least-squares or downstream-derived coefficient.
- **Nash-MTL:** two tasks; `update_weights_every=1`, `optim_niter=20`, ECOS solver, previous alphas initialized to ones, original stopping criteria. The official helper's internal norm-1 clip is disabled because the shared GraphMAE2 full-model norm-3 clip applies once. Log solver status and applied `alpha_rec, alpha_lat` each update; a failed solve is recorded as a scientific failure, not silently replaced by the previous alpha. Valid direct-Rhat relative coefficient is `alpha_lat/alpha_rec` with finite positive denominator.
- **FAMO:** two tasks; official `gamma=0.01`, `w_lr=0.025`, task logits initialized to zero, minimum losses initialized to zero. The helper's internal norm-1 clip is disabled; the common full-model norm-3 clip applies. Evaluate the same training batch again after the model optimizer step for FAMO's state update, under `no_grad` and with the original graph, features, masks, teacher state, and model training mode. Snapshot/restore RNG around that replay so the next frozen update sees its original RNG state; if this cannot be verified, stop. Log the softmax state and actual **pre-step applied** positive multipliers `z_i / (c D_i)` with `D_i=L_i-min_i+1e-8`, detached `c=sum(z_i/D_i)`. Use their ratio for direct R-hat only if both are finite and the reconstruction multiplier is positive.
- **Checkpoint attribution for all three:** the coefficient linked to checkpoint update `u` is exactly the last coefficient **used to compute the model optimizer step that completed update `u`**. Write `optimizer_updates_completed -> applied coefficient(s)` in the trajectory and checkpoint manifest. Do not use post-step auxiliary state as a substitute, a neighboring update, or an average window. Preserve post-step method state separately for resume.
- Nonfinite coefficient, nonpositive required denominator, unsupported solver state, missing task gradient, or an unvalidated transformation is logged as such. No silent fallback or inferred coefficient is allowed. Aligned-MTL may retain only its explicitly labeled pre-transformation measurement.

## Downstream and compute rules

- Seven checkpoint validation accuracies per seed use the same frozen linear-probe protocol. Normalized validation-trajectory AUC is the trapezoidal area over the seven fixed update coordinates divided by `8532-250`. Report every per-seed AUC, three-seed mean and sample SD, and matched seed differences against Ours lambda=0.3, Equal lambda=1, and Original lambda=10. Do not tune method settings from validation. Paired n=3 tests are not the primary evidence.
- Direct R-hat measures the reconstruction and raw latent component gradients on shared target-node representation `Z_T`, with the applicable completed-update relative weight. Report each method/seed/checkpoint and all diagnostic batches, plus coefficient provenance. Never claim parameter-space Aligned-MTL transformation is equivalent to a scalar representation-space coefficient without direct proof.
- The ten-method overhead benchmark is separate from formal training: one machine, one GPU, same model/data/batch128 and method defaults, 50 warm-up optimizer steps plus 300 measured steps. Fixed order: Original lambda=10, Ours lambda=0.3, Equal lambda=1, GradNorm, Uncertainty, CoV, PCGrad lambda=10, Aligned-MTL, Nash-MTL, FAMO. Warm-up is excluded. Capture per-step elapsed time (GPU synchronized), total measured time, mean/median, peak allocated and reserved GPU memory, hardware/software and background-process state. Benchmark has no downstream evaluation and is not mixed with historical full-run wall times.

## Hypotheses and reporting discipline

- **H1:** Under matched seeds, Aligned-MTL, Nash-MTL, and FAMO validation-trajectory AUCs may lie near the existing higher-performing weighting methods. No particular new method is assumed better or worse than candidate lambda=0.3.
- **H2:** Similar downstream performance need not imply equal directly measured representation-level dominance; different weighting mechanisms may have different realized ratios.
- **H3:** At least some dynamic SOTA methods may incur additional training computation compared with Equal lambda=1, without prespecifying magnitude.

These are hypotheses, **not gates for inclusion**. Report every completed formal run, including a new method outperforming lambda=0.3. If results contradict the manuscript's Section 5.2, revise the manuscript after human review; do not exclude the result. This extension follows the AE desk reject and does not retroactively repair the missed earlier prospective lambda=3/6 window.

## Failure and launch gates

- Before any formal seed: source/core hash audit, offline engineering checks, and an independent smoke for each of the three methods. Smoke checks both losses/gradients, method-state change, correct backward/model update, unchanged teacher/target/RNG schedule, checkpoint save/load, diagnostic state preservation, solver/transformation or same-batch replay as applicable, and timing/memory logging. Smoke is for correctness only, not performance selection.
- Scientific failure (method-originated NaN/Inf, divergence, solver instability, collapsed weights, transformation instability, or method-originated OOM at fixed config): keep raw logs and failure update; do not change hyperparameters and rerun until success. An OOM requires a report before any batch-size change.
- Infrastructure failure (power loss, restart, driver crash, unrelated-process OOM, storage failure, scheduler error, or explicit interruption): rerun only the same frozen config, with original/replacement run IDs, timestamp, cause and resume provenance in the failure ledger.
- Never automatically modify the manuscript from intermediate results. Formal results and audit bundle must be reviewed first.
